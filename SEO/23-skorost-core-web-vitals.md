# Урок 23. Скорость сайта и Core Web Vitals

## Core Web Vitals (Google, 2020+)

Три ключевые метрики пользовательского опыта:

### 1. LCP (Largest Contentful Paint)
- **Что:** время отрисовки самого крупного элемента на экране.
- **Хорошо:** ≤ 2.5 сек.
- **Плохо:** > 4.0 сек.
- Что обычно влияет: картинки hero-блока, видео-постеры, большие текстовые блоки.

### 2. INP (Interaction to Next Paint) — заменил FID с 2024
- **Что:** время отклика на взаимодействие пользователя.
- **Хорошо:** ≤ 200 мс.
- **Плохо:** > 500 мс.
- Что обычно влияет: тяжёлый JS, долгие обработчики событий.

### 3. CLS (Cumulative Layout Shift)
- **Что:** визуальная стабильность — сумма неожиданных сдвигов макета.
- **Хорошо:** ≤ 0.1.
- **Плохо:** > 0.25.
- Что обычно влияет: картинки без размеров, динамическая вставка контента, шрифты.

## Инструменты измерения

- **PageSpeed Insights** — лаборатория + полевые данные (CrUX).
- **Lighthouse** — в Chrome DevTools.
- **Web Vitals** (расширение Chrome).
- **CrUX Dashboard** в GSC → Опыт использования.
- **GTmetrix**, **Pingdom** — лабораторные.

## Как улучшить

### Серверная оптимизация
- **CDN** (Cloudflare, AWS CloudFront, Fastly).
- **HTTP/2 или HTTP/3**.
- **GZIP / Brotli** сжатие.
- **Кэширование** на стороне сервера.
- **TTFB** < 600 мс (время до первого байта).

### Изображения
- WebP/AVIF формат.
- Lazy loading.
- Адаптивные размеры (srcset).
- Сжатие (TinyPNG, Squoosh, ShortPixel).
- Указание размеров в HTML.

### CSS / JS
- Минификация.
- Critical CSS inline.
- Удаление неиспользуемого CSS/JS.
- Defer / async для скриптов.
- Tree-shaking.
- Code splitting.

### Шрифты
- `font-display: swap`.
- Подмножества шрифтов.
- Предзагрузка важных шрифтов.

### HTML
- Сжатие (GZIP/Brotli).
- Минификация.
- Удаление комментариев и пробелов.

### Другое
- Убрать тяжёлые сторонние скрипты (аналитика, чаты, реклама).
- Preload / prefetch для важных ресурсов.
- Service worker для оффлайн-кэша.

## Влияние на SEO
- **Подтверждённый фактор ранжирования** (с 2021).
- Страницы с хорошими CWV ранжируются выше.
- Особенно важно для мобильных.
- Влияет на индексацию: медленные страницы краулятся реже.

## Mobile vs. Desktop
- Google Mobile-First Indexing — индексирует мобильную версию.
- Mobile CWV — важнее.
- На мобильных обычно всё медленнее.

## Стратегия работы
1. **Замерьте** — PageSpeed Insights + CrUX.
2. **Найдите bottleneck** — Largest Contentful Paint, JS-блокирующие скрипты.
3. **Исправьте top-3 проблемы**.
4. **Перемерьте**.
5. **Мониторьте** — еженедельно.

## Чек-лист урока
- [ ] LCP < 2.5 сек, INP < 200 мс, CLS < 0.1.
- [ ] Изображения в WebP/AVIF, с lazy loading.
- [ ] JS defer/async, нет блокирующих скриптов.
- [ ] Включено GZIP/Brotli.
- [ ] Используется CDN.
