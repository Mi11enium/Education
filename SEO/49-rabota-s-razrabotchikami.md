# Урок 49. Взаимодействие SEO и разработки

## Почему важно
- 70% технических SEO-задач требуют участия разработчика.
- Плохая коммуникация = задержки, конфликты, баги.
- Разработчики часто не знают SEO-требований.

## Что должен знать разработчик о SEO

### Минимум
- Что такое Title, Description, H1.
- robots.txt, sitemap.xml.
- Canonical и редиректы.
- HTTPS.
- Скорость и CWV.
- Mobile-friendly.

### Базовые задачи
- Настроить редирект 301.
- Добавить canonical.
- Закрыть страницу в robots.txt.
- Внедрить Schema (если есть шаблон).
- Оптимизировать картинки.

## Как ставить задачи

### Плохой запрос
> «Сделай SEO нормальным»

### Хороший запрос
**Шаблон задачи:**

```markdown
## Задача
Настроить 301-редирект со старого URL на новый.

## Зачем
Изменили структуру каталога. Без редиректа потеряем позиции.

## Где
Сервер: production.
Файл: .htaccess / nginx config.
Или: WP-плагин Redirection.

## Как сделать
С конкретным URL:
`/old-category/old-product/` → `/new-category/new-product/`

## Тест
Проверить:
1. `curl -I https://example.com/old-product/` → 301.
2. Браузер → ввод URL → редирект на новый.
3. GSC → URL Inspection → канонический.

## Приоритет
Высокий (потеря трафика).

## Срок
До конца недели.
```

## Где фиксировать задачи
- **Jira, Asana, Trello** — классика.
- **Notion** — документация + задачи.
- **Linear** — для разработки.
- **GitHub Issues** — для open source.

## Приоритезация
**ICE / RICE-фреймворки:**

### ICE
- **Impact** — влияние на SEO.
- **Confidence** — уверенность, что сработает.
- **Ease** — насколько легко сделать.

### RICE
- **Reach** — сколько страниц/запросов затронет.
- **Impact** — влияние (от 0.25 до 3).
- **Confidence** — уверенность.
- **Effort** — трудозатраты (человеко-дни).

## Типичные задачи

### Срочно
- 4xx ошибки на важных страницах.
- HTTPS не настроен.
- Сайт под фильтром.
- Скорость критически упала.

### Высокий приоритет
- Canonical не настроен.
- Schema не внедрена.
- Пагинация ломает индексацию.
- Mobile UX плохой.

### Средний
- Дополнительные блоки Schema.
- Оптимизация картинок.
- Расширение hreflang.

### Низкий
- Косметические правки.
- Изменение порядка блоков.

## Как убедить разработчика

### Аргументы
1. **Цифры** — потенциальный трафик / деньги от SEO.
2. **Примеры конкурентов** — «вот у них это есть».
3. **Простые задачи** — давайте сначала маленькие.
4. **Чек-листы** — Google рекомендует.
5. **Документация** — что именно нужно сделать.
6. **Метрики** — покажите, как изменилось.

### Чего НЕ делать
- ❌ «SEO важнее всего».
- ❌ «Просто сделай».
- ❌ Обвинять в падении позиций (без доказательств).
- ❌ Постоянные срочные задачи.

## Документация для разработчиков

### Что подготовить
- **SEO-чеклист для разработки** (требования к релизам).
- **Спецификации для компонентов** (Title, Schema, Meta).
- **Примеры кода** (canonical, hreflang, Schema).
- **Definition of Done** для SEO-задач.

### Definition of Done (пример)
Для задачи «Опубликовать новую категорию»:
- [ ] Title и Description уникальны.
- [ ] Canonical указывает на себя.
- [ ] H1 с ключом.
- [ ] Schema/ItemList.
- [ ] Breadcrumbs.
- [ ] Перелинковка с 3+ страниц.
- [ ] Внутренняя проверка Screaming Frog.
- [ ] Проверка PageSpeed > 80.
- [ ] GSC → URL Inspection без ошибок.

## Регулярные встречи
- **Weekly sync** — что в работе, что заблокировано.
- **Sprint review** — показ результатов.
- **SEO-ревью** перед каждым релизом.
