# Урок 22. Редиректы и коды ошибок

## HTTP-коды ответов

### Информационные (1xx)
- `100 Continue` — промежуточный.

### Успешные (2xx)
- `200 OK` — страница доступна.

### Редиректы (3xx)
- `301 Moved Permanently` — постоянный редирект (передаёт PageRank).
- `302 Found` — временный редирект (НЕ передаёт полный PageRank).
- `303 See Other` — для POST-форм.
- `307 Temporary Redirect` — сохраняет метод запроса.
- `308 Permanent Redirect` — постоянный с сохранением метода.

### Ошибки клиента (4xx)
- `400 Bad Request` — синтаксис.
- `401 Unauthorized` — требуется авторизация.
- `403 Forbidden` — запрещено.
- `404 Not Found` — не найдено.
- `410 Gone` — удалено навсегда.
- `429 Too Many Requests` — слишком много запросов.

### Ошибки сервера (5xx)
- `500 Internal Server Error` — внутренняя ошибка.
- `502 Bad Gateway` — шлюз.
- `503 Service Unavailable` — сервер недоступен.
- `504 Gateway Timeout`.

## Когда использовать редиректы

| Сценарий | Код |
|---|---|
| Сайт переехал на новый домен | 301 |
| Переход с HTTP на HTTPS | 301 |
| С www на без www (или наоборот) | 301 |
| Изменение URL страницы | 301 |
| A/B тест страниц | 302 / 307 |
| Временный технический даунтайм | 503 |

## Цепочки редиректов

❌ **Плохо:** A → B → C → D (3+ шага).
✅ **Хорошо:** A → D (1 шаг).

Каждый редирект теряет ~10–15% PageRank. Цепочки замедляют загрузку.

## Soft 404
Страница отдаёт HTTP 200, но по факту пустая/неинформативная.
Google может считать её за дубль или понизить.
- ❌ `/old-page` отдаёт «Страница не найдена» с кодом 200.
- ✅ `/old-page` должна отдавать 404 или редиректить 301.

## Настройка редиректов

### Apache (.htaccess)
```
Redirect 301 /old-page https://example.com/new-page
RedirectMatch 301 ^/old/(.*)$ https://example.com/new/$1
```

### Nginx
```
rewrite ^/old-page$ https://example.com/new-page permanent;
```

### WordPress
- Плагины: Redirection, Yoast Premium.
- Вручную: в .htaccess.

### 1С-Битрикс
- Настройки → Редиректы (правила urlrewrite.php).

## 404 ошибки

### Когда это нормально
- Старая страница удалена, редирект не нужен.
- Опечатка в URL.

### Когда это плохо
- Часто возникающие 404 (битые внутренние ссылки).
- 404 на страницах с трафиком/бэклинками.
- Массовые 404 после редизайна.

### Что делать
1. Аудит в GSC → Покрытие → Исключено.
2. Screaming Frog → Response Codes → Client Error (4xx).
3. Ahrefs/SEMrush → Broken Links.
4. Настройте 301-редиректы на релевантные страницы.

## 410 Gone
Используйте, когда страница удалена **навсегда** и редирект не нужен.
Google быстрее убирает такие URL из индекса.

## Проверка
- `curl -I https://example.com/page` (заголовки).
- **Redirect Path** (расширение Chrome).
- **httpstatus.io** (массово).
- **Screaming Frog**.

## Чек-лист урока
- [ ] Изменения URL — всегда через 301.
- [ ] Нет цепочек редиректов >1.
- [ ] Нет soft 404.
- [ ] Битые ссылки исправляются регулярно.
- [ ] HTTP→HTTPS через 301.
