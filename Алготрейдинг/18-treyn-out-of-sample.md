# Урок 18. Train / Test / Out-of-Sample

## Зачем разделять данные
Главный враг алготрейдера — **переобучение (overfitting)**. Если вы подбирали параметры на тех же данных, что и оцениваете — результат нереалистичен.

## Структура выборки

```
┌──────────────────────────────────────────┐
│           Full Historical Data            │
└──────┬──────────────┬──────────┬─────────┘
       ↓              ↓          ↓
  ┌─────────┐   ┌──────────┐ ┌────────┐
  │ Train   │   │Validation│ │  Test  │
  │ (In-    │   │(Out-of-  │ │(Hold-  │
  │ sample) │   │ sample)  │ │ out)   │
  └─────────┘   └──────────┘ └────────┘
   60-70%        15-20%        10-20%
```

### Train (In-sample)
- Подбор параметров стратегии.
- Максимизация метрик.

### Validation (Out-of-sample-1)
- Сравнение разных стратегий / конфигураций.
- Выбор финалистов.

### Test (Out-of-sample-2 / Hold-out)
- Финальная оценка.
- **Одноразовый замер**, не использовать для донастройки.

## Правила

### 1. Строгое разделение
- Тестовые данные **не должны** использоваться при подборе параметров.
- ❌ «Подобрал на 2020–2024, проверил на 2020–2024» — не out-of-sample.

### 2. Размер выборки
- Train: ≥ 5 лет (для дневных стратегий).
- Test: ≥ 1 года, лучше 2–3.
- **Walk-forward** предпочтительнее (см. урок 25).

### 3. Честность
- Если результат на test плохой — стратегия не работает.
- ❌ Не «дообучать» на test.

### 4. Multiple test correction
- Если много стратегий тестируется на test — нужна коррекция.

## Проблемы

### 1. «Я знал, что будет»
Если вы помните кризис 2020, вы невольно оптимизируете под него.

### 2. Regime change
- Стратегия работала 2010–2019, перестала в 2020.
- Out-of-sample может «удачно» попасть в стабильный режим.

### 3. Survivorship в данных
- Данные могут содержать только выжившие тикеры.

## Реализация в Python

```python
# Простой split
train = data.iloc[:int(len(data) * 0.7)]
val = data.iloc[int(len(data) * 0.7):int(len(data) * 0.85)]
test = data.iloc[int(len(data) * 0.85):]

# Walk-forward
def walk_forward(data, train_size, test_size):
    for start in range(0, len(data) - train_size - test_size, test_size):
        train = data.iloc[start:start + train_size]
        test = data.iloc[start + train_size:start + train_size + test_size]
        yield train, test
```

## Шаги

### 1. Собрать данные
- Максимально длинная история.
- Разные режимы (bull, bear, flat, high/low vol).

### 2. Разделить
- Train: 2010–2018.
- Val: 2019–2020.
- Test: 2021–2024.

### 3. Оптимизировать на train
- Параметры стратегии.
- Без заглядывания в val/test.

### 4. Отобрать на val
- Sharpe, MaxDD, Profit Factor.
- Выбрать 1–3 финалистов.

### 5. Финально проверить на test
- **Один раз**.
- Зафиксировать результат.

### 6. Запуск
- Только если результат на test приемлем.

## Типичные ошибки

❌ Оптимизация на полной выборке.
❌ Подбор параметров на test.
❌ «Случайное» удаление плохих сделок.
❌ Подмена дат.
❌ Подмена условий (вы поменяли SL после плохого трейда).

## Альтернативы

### Cross-Validation
- K-fold (для трейдинга — purged K-fold).
- ⚠️ Для временных рядов обычный K-fold некорректен (утечка данных).

### Combinatorial Purged CV (CPCV)
- Lopez de Prado.
- Несколько backtest paths.
- С учётом purging/embargo.

## Метрики для теста

### Обязательные
- Sharpe (annualized).
- MaxDD.
- Total PnL.
- Profit Factor.

### Дополнительные
- Calmar.
- Sortino.
- Win Rate.
- Avg Trade.

### Сравнение с baseline
- Buy & hold.
- Random strategy.
- Naive MA crossover.
