# Урок 3. Архитектура торгового робота

## Компоненты типичной системы

```
┌─────────────────────────────────────────────────┐
│  DATA LAYER                                     │
│  Market Data Feed (исторические + live)         │
└──────────────────┬──────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────┐
│  STRATEGY LAYER                                 │
│  Feature Engineering → Signal Generation        │
└──────────────────┬──────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────┐
│  RISK & SIZING LAYER                            │
│  Position Sizing → Pre-trade Risk Check         │
└──────────────────┬──────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────┐
│  EXECUTION LAYER                                │
│  Order Management → Smart Order Routing         │
└──────────────────┬──────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────┐
│  PORTFOLIO & MONITORING                         │
│  PnL → Risk Limits → Alerts → Logging           │
└─────────────────────────────────────────────────┘
```

## Подробнее о каждом слое

### 1. Data Layer
- **Источник**: биржа, брокер, data vendor (Polygon, Databento, Quandl).
- **Типы данных**:
  - L1 (bid/ask/last, volume).
  - L2 (стакан).
  - L3 (полный order book).
  - Trades (тиковые данные).
  - Reference (расписание торгов, дивиденды, сплиты).
- **Хранение**: parquet, HDF5, Arctic, TimescaleDB, InfluxDB.

### 2. Strategy Layer
- **Feature Engineering**: расчёт индикаторов, лагов, скользящих окон.
- **Signal**: логическое решение (long/short/flat).
- **Модульность**: стратегия как класс/функция, легко заменяемая.

### 3. Risk & Sizing Layer
- **Position Sizing**: сколько контрактов.
- **Pre-trade check**:
  - Не превышен ли лимит?
  - Достаточно ли маржи?
  - Не сработает ли stop-out?
- **Drawdown-контроль**: уменьшение размера после серии убытков.

### 4. Execution Layer
- **Order types**: market, limit, stop, stop-limit, IOC, FOK, GTC.
- **Smart routing**: где лучше ликвидность.
- **TWAP/VWAP**: нарезка крупных ордеров.
- **Slippage control**: icebergs, dark pools.

### 5. Portfolio & Monitoring
- **Real-time PnL**.
- **Margin usage**.
- **Exposure**: суммарная позиция, по секторам.
- **Alerts**: превышение лимита, потеря связи, аномалии.
- **Logging**: каждый тик, каждое решение (для аудита).

## Стили архитектуры

### Монолит
- Всё в одном процессе.
- ✅ Просто разрабатывать.
- ❌ Сложно масштабировать.

### Микросервисы
- Каждый слой — отдельный сервис.
- ✅ Масштабируемо, отказоустойчиво.
- ❌ Сложнее, latency overhead.

### Event-driven
- Всё через очередь событий (Kafka, Redis Streams).
- ✅ Гибко, decoupled.
- ❌ Нужен опыт.

## Точка принятия решения

```
Market Data → [Feature Calc] → [Signal] → [Risk Check] → [Order] → [Send]
```

Время от тика до отправки ордера = **latency**.
- HFT: <1 мс.
- Скальпинг: 1–10 мс.
- Интрадей: 10–100 мс.
- Свинг: 100+ мс.

## Хранение состояния
- **Stateless** — без состояния между тиками (проще).
- **Stateful** — с позицией, очередью ордеров, PnL (нужно сохранять).

Восстановление после падения: snapshot + WAL.
